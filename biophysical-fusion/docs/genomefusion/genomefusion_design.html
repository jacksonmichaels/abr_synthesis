Design · follow-up to LocusFusion v5 · 4 Nov 2026

GenomeFusion

LocusFusion extended from 19 hand-picked loci to the whole H37Rv genome. Every base belongs to exactly one locus: a gene, or the intergenic segment between two genes. Only loci the isolate actually changes enter the network, and a locus can hold any number of variant tokens.

Status: built 4 Nov 2026 in biophysical-fusion/genomefusion/; numbers below marked as built are measured, the rest are the design. Genome numbers are counted from data_snapshot/genbank/genome.gbff (NC_000962.3). Token-count estimates are marked as estimates.

The partition: one locus per base

H37Rv is 4,411,532 bp. Its 4,008 annotated genes cover 90.3% of it. The rest falls into 3,050 intergenic segments.

4,008genes: 3,906 CDS, 45 tRNA, 3 rRNA, 20 ncRNA, 34 other; 30 marked pseudo
3,050intergenic segments; median 80 bp, mean 140 bp, max 4,588 bp
378segments of 10 bp or less
13,121bases that lie in two genes (0.3% of the genome)

6,776as built: 3,749 gene + 3,027 intergenic loci after masking
9.1%as built: 402,567 bp masked — 773 RLC regions plus 254 PE/PPE and IS/phage genes
881as built: mean tokens per isolate (15.8M over 17,943 isolates)
707as built: mean active loci per isolate; ~1.2 tokens each

The token estimate held: 881 tokens per isolate against the 500–1,500 predicted. The active-locus count confirms the concern raised below — most active loci carry a single token.

The last number is why the partition has to be strict. A fixed 100 bp upstream window for every gene would put most windows partly inside a neighbour's coding sequence. The same base would then be a token in two loci and be counted twice. Instead:

  • Genes are loci, as annotated, with coordinates from the start codon as in v3.
  • Intergenic segments are loci. A segment's regulatory role is a token channel, upstream of: the distance to the next start codon downstream on the + strand and on the − strand, with −1 when the segment doesn't sit upstream of a gene on that strand.
    • A divergent segment (Rv1482c ← | → fabG1) is upstream of both genes. The inhA-promoter c-15t, at 1,673,425, reads 15 bp upstream of fabG1 and 126 bp upstream of Rv1482c.
    • A co-directional segment is upstream of one gene.
    • A convergent segment is upstream of neither.
  • Overlapping genes (embA/embB share 4 bp, ATGA-type stop/start overlaps are common): each overlap base goes to the gene whose start codon it is closer to, so start codons stay whole. The token's overlap flag is set.
    • As built, this has a cost: 840 coding sequences lose a base of their STOP codon to a neighbour's start codon — pncA among them. Counting RLC-masked bases too, 951 of 3,680 CDS (25.8%) have at least one incomplete codon, 4,342 codons in all, about 0.3% of the genome's codons. A token in an incomplete codon is called unreadable, never a false nonsense.
  • Masked loci: PE/PPE and PE_PGRS genes, IS6110 and other insertion sequences, phage regions and repeats are dropped before tokenizing. Reads map unreliably there, and their artefacts would be the loudest variants in the genome. The exact list (a published low-confidence mask) is still to be chosen and counted.

The token

This is the v5 token, which is v3's residue one-hot plus consequence and site proximity, with synonymous changes dropped. GenomeFusion folds v5's separate regulatory-base slot into a single base slot, because the region channel now says where the base is. It expands the consequence one-hot and adds the channels marked new:

The population channels use genotypes only, never labels, so they are not a leak. They are an arm, not a default.

Where tokens come from: the VCFs

Each isolate has one Pilon 1.24 VCF, normalised with bcftools norm, so every indel is left-aligned and the same event is spelled the same way in every isolate. The file was then filtered with bcftools view --types snps,indels,mnps,other. That keeps only sites with an alternative allele and drops every reference call. One isolate checked (SAMEA104394571) has 1,382 records:

  • 1,225 SNPs, 81 deletions and 76 insertions;
  • 1,015 PASS; the rest are flagged LowCov, Amb or Del;
  • 23 IMPRECISE records. The structural ones are ~900 bp insertions, consistent with IS6110 transpositions.

QC follows the existing extractor's allele_category: a record is called alt, ref or missing using FILTER, allele fraction, QUAL, DP, MQ and BQ.

The coverage gap

A stretch with no reads and no alternative allele leaves no record, so it reads as reference. GenomeFusion cannot make uncalled-region tokens from these files. "No token" means "matches H37Rv or was not covered".

This is not new. v3's N channel has always meant "low-quality variant call", never "no coverage", because its MSAs come from the same VCFs. Genome-wide it matters more: deletions Pilon did not resolve (often in RD regions) become wild-type, and coverage across 7,000 loci is worse than at the 19.

Closing the gap needs coverage data. The VCF headers point to full Pilon VCFs (*_full.vcf.gz) and BAMs on the Farhat lab's server, which Unity cannot reach. A per-isolate BED of low-coverage regions would be enough.

Frameshifts

v3–v5 read residues on the H37Rv codon grid (datasets/biochem.translate_reference_frame). Codon k is always the isolate's bases at reference codon k's three columns. That is right: translating in the isolate's own frame would turn every residue after a 1 bp deletion into a false substitution. The cost is that the shifted frame is invisible:

  • A frameshift appears only as the changed columns, consequence "other".
  • A 1 bp deletion (one - token) and a 3 bp in-frame deletion (three tokens) can only be told apart by counting modulo 3.
  • Nothing says how much protein is lost after the event.

GenomeFusion keeps the reference grid and no tokens are emitted for out-of-frame codons. The frame information goes into explicit channels instead:

  1. One token per indel event. The length goes in span. Because the VCFs are normalised, the same indel is spelled identically in every isolate.
  2. Named consequences. An indel with length mod 3 ≠ 0 is a frameshift; otherwise it is an in-frame indel. Start-loss, stop-loss and unreadable each get their own channel.
  3. Truncation. The fraction of the CDS after the event, for frameshifts, nonsense changes and start-loss. A frameshift at codon 10 of pncA reads about 0.95; one in the last codons reads near 0.
  4. Frame summary on [NULL]. For each isolate and locus, add up the indels in order and record two values: the net frame offset at the end of the CDS, and the fraction of the CDS read out of frame. A +1 and a −1 a few codons apart give a net offset of 0, but a nonzero out-of-frame fraction.
  5. Homopolymer flag. Set for indels in runs of five or more identical bases. These are the likeliest calling errors, and also where real phase variation happens, so they are flagged and kept.

Precise indels make this deterministic once a record passes QC. IMPRECISE records and indels the QC turns into N have no reliable length; they get consequence unreadable.

The network

  1. Token embedding. Linear 53 → 128, plus a sinusoidal position within the locus (from the start codon for genes, from the 5′ end of the segment for intergenic loci), plus the locus embedding.
  2. Within each active locus. Only loci with at least one token are encoded. All (isolate, locus) pairs in a batch are packed into a flat list and bucketed by token count, so each bucket is padded only to its own width. A dense (B, loci, tokens, C) tensor would be about 80× the real data, because the median locus carries one token and the busiest carries about 90. The [NULL] token carries four values on top of the locus features: the token count, the total span, the net frame offset and the out-of-frame fraction. The encoder is a shared 2-layer transformer with FiLM, and the locus vector is the output at [NULL].
  3. Across active loci. A 2-layer transformer over the active-locus vectors plus one learned reference token, with a padding mask. Isolates differ in how many loci are active.
  4. Readout. One learned query per drug attends over the active loci and the reference token, then an MLP (128 → 256 → 1) gives P(resistant).

Variable length

The output shape is fixed whatever the number of active loci, because attention pooling is a weighted sum: every isolate ends with (n_drugs, 128). Only the intermediate tensors vary in length:

  • Within loci, sequences are packed with a block-diagonal mask, so there is no padding.
  • Across loci, sequences are padded to the batch's own maximum, never to 6,776. A sampler that groups isolates with similar active-locus counts keeps that padding to a few percent. At 32 isolates × 1,500 loci × 128 dims (fp32) it is about 25 MB either way.

Two consequences of dropping loci:

  • Row position no longer means a locus. Identity comes only from the locus embedding, and there is no positional encoding along the locus axis.
  • The reference token gives attention somewhere to go. A susceptible isolate may have nothing relevant active. Without the reference token, softmax would push each drug query onto some lineage SNP instead.

Locus identity at 7,000 loci

v5 learns a free 128-d embedding and a free scale/shift for each locus. At 6,776 loci that is about 2.7M parameters, most for loci that vary in a handful of isolates. GenomeFusion predicts all three from a locus feature vector and adds a small learned residual with strong weight decay and dropout. The features are:

  • region type, length, strand and genome position;
  • functional category (Mycobrowser) and in-vitro essentiality (TnSeq), both of which still need to be fetched;
  • WHO catalogue tier and membership of the current 19;
  • for intergenic segments: orientation class and the flanking genes' features.

The current 19 loci keep a strong signal through their own residuals and tier features.

Size

Estimate, to be measured from the variant table: clinical isolates differ from H37Rv at roughly several hundred to about two thousand positions, more for lineages far from H37Rv (lineage 4). After masking and dropping synonymous changes, I expect around 500–1,500 tokens per isolate, spread over a similar number of active loci. Attention over sequences of that length is routine. The unique-variant table is annotated once, and each isolate is stored as a list of int32 indices into it. For 17.9k isolates that is a few hundred MB at most, rather than a dense cache.

If there is no cap, do loci still matter?

Yes, in four places. Whether they help is an experiment, and the plan includes it as the flat arm.

The alternative is not a dense matrix over the genome. That would be 4.4 million positions per isolate, and no one proposes it. The real alternative is a flat set of the same sparse variant tokens with one transformer over all of them. Both models see the same tokens at about the same cost. They differ only in the constraints the loci impose.

  1. Attention neighbourhoods. In stage 1 a token attends only to tokens in its own locus. That is a block-diagonal mask, an inductive bias that interactions between variants are mostly within one gene: a frameshift and the changes downstream of it, two hits in katG, compensatory changes within rpoB.
  2. A bottleneck at the unit biology acts on. Each locus becomes one vector before anything else sees it. Resistance by loss of function (pncA, ethA, gid, Rv0678, katG) comes from hundreds of different rare alleles that all mean "this gene is broken". The [NULL] summary gives them one shared slot, and its count and span inputs give a gene-level burden. A flat model can learn the same thing only if the drug query learns to attend to every token carrying that locus's embedding, with the softmax spread over about 1,000 tokens.
  3. The coordinate frame. Codon phase, residue identity, Δ properties and binding-site distance are all defined relative to a gene's start codon. The flat model still needs this per-token annotation. It just doesn't group by it.
  4. Identity, FiLM and the readout. Loci carry the learned identity and modulation, and they are what the drug queries attend over. The readout's attention is then a per-gene attribution, which is the interpretable output a genome-wide model is for.

Something to expect: genome-wide, most active loci will hold a single token, because a lineage SNP lands in a gene alone. For those loci, stage 1 is close to an MLP on one token, and the hierarchy does nothing extra. It earns its keep only at loci that collect several tokens, and those are mostly the resistance genes. The flat arm is cheap to build from the same code: skip stage 1, add the locus embedding to every token, and let the drug queries attend over tokens. If flat ties GenomeFusion on the 55 lineage folds, the hierarchy is not paying for itself at genome scale.

Revision to my earlier note. I suggested dropping variants seen in fewer than k isolates. That would discard exactly the rare pncA/ethA alleles that point 2 depends on. Tokens are described by features, never by a variant ID, so a singleton can't be memorised by name anyway. Keep rare variants. Handle population structure with the optional homoplasy and lineage-marker channels, and with the lineage split itself.

Population structure

Genome-wide, the cheapest predictor of resistance is lineage: Beijing markers, and SNPs that ride along in MDR clades. The lineage split (Beijing in its own fold) is the right test, because a held-out lineage's markers can't help. Markers will still take up model capacity, though, and light up in attribution. The pop arm adds the homoplasy and marker channels. Convergent evolution (a variant arising independently many times) is the established genome-wide resistance signal, and it separates real candidates, including compensatory rpoC/rpoA and ahpC-promoter changes, from clade markers.

Experiments

All runs use the lineage split, 55 CV folds and the exact Wilcoxon test against LocusFusion v3 and v5, the same protocol as the locus-sets sweep. Single-drug first, then the 11-drug model.

Build order

  1. Variant table. Read the per-isolate VCFs once into (New_ID, pos, ref, alt), as a CPU SLURM job. The VCFs are in the read-only pi_annagreen tree on the flaky /project mount, so check the mount on a compute node and write only to scratch. Use the indel handling from the fixed extractor (the July 2025 insertion bug).
  2. Partition and annotation. Assign genome positions to loci, apply the mask, and annotate each unique variant once (locus, codon, consequence, truncation, properties, distance, upstream-of, overlap, homopolymer). Then compute the per-isolate, per-locus frame summaries.
  3. Data checks.
    • Parity with the v5 tokenizer at the 19 loci. Differences are expected only for shared bases, indel tokens (now one per event) and the insertion-bug fix.
    • Known deletions should follow lineage: RD105 in essentially every Beijing isolate and almost none of the others.
    • Per-isolate distributions of span count, deleted bases and N count, to flag poor-quality samples.
    • Frameshifts with truncation > 0.5 at pncA, ethA, katG and Rv0678 should on their own predict PZA, ETO, INH and BDQ/CFZ resistance well.
  4. Sparse model on the 19 (gf19), which should match v5 within fold noise.
  5. Genome-wide canary on one drug, PZA (the pncA loss-of-function case), then the grid via sbatch_all_runs.py, dry run first.

Open decisions

  • Coverage data: whether the full Pilon VCFs or low-coverage BEDs can be obtained, or the first version accepts "no token = reference or not covered".
  • Which low-confidence mask: a published Mtb mask, or PE/PPE + IS + phage from the GenBank annotation alone.
  • Whether to keep the across-loci self-attention, or switch to Perceiver-style latents if the number of active loci per isolate turns out larger than estimated.
  • Where the locus features come from: Mycobrowser categories and TnSeq essentiality need a download.
  • Which synonymous changes to keep beyond v4's exclusion list (fabG1 L203L), for example near start codons.
